# Private ClamAV HTTPS adapter

This service is supplied for existing approved infrastructure. No infrastructure, paid service or subscription has been created. It has no public scanning-provider integration. It uses Node standard libraries and sends the actual uploaded bytes to an internal ClamAV daemon with INSTREAM; a filename or declared MIME type never produces a clean verdict.

Deploy behind your existing authenticated, private HTTPS ingress with a currently valid trusted certificate. Keep the HTTP container port and clamd TCP port on the private network; do not expose clamd or the raw adapter to the public Internet. The application needs outbound access from Vercel to the approved HTTPS ingress. A private RFC1918-only endpoint requires an existing network path; configuring its name does not create connectivity. Pin the approved Node image digest and existing ClamAV image/version in your deployment manifest. Update ClamAV signature definitions with the organization's approved freshclam schedule and monitor freshness.

Service configuration (server only): `SYNAPSE_SCANNER_TOKEN` (at least 32 random characters), `CLAMAV_HOST`, `CLAMAV_PORT` (usually 3310), `BIND_HOST` and `PORT`. Use a separate secret from Gmail, Supabase and CRON_SECRET. Both `/health` and `/scan` require `Authorization: Bearer ...`. The external URL must be HTTPS; TLS termination belongs to the approved ingress. Never disable certificate verification.

SYNAPSE Vercel Production configuration: `SYNAPSE_SCANNER_URL=https://<approved-private-scanner-host>/scan`, `SYNAPSE_SCANNER_TOKEN` matching the private service, `SYNAPSE_SCANNER_PRIVATE_APPROVED=true` only after approving that exact endpoint. Do not use NEXT_PUBLIC variables. Keep settings in the existing ignored local integrations file for preparation; never commit values. Redeploy after changing Vercel settings.

The client posts `application/octet-stream`, limits uploads to 2 MiB, forbids redirects and uses a 20-second deadline. The adapter limits request size/time, caps ClamAV replies and connects only to its configured daemon. Responses include explicit verdict, actual SHA-256/byte count, engine/version, scan UUID and time. SYNAPSE validates the schema, hash, size and freshness before recording provenance. INFECTED, INDETERMINATE, malformed replies, unavailable daemon, timeouts, HTTP errors or mismatched hashes never clear quarantine. Plain text also requires actual ClamAV clearance in hosted mode. Demo/isolated historical text policy is separate.

The approved officer scans an original Gmail attachment in Intake or case evidence in its complaint page. Each attempt is authorized on the server, and successful results are reauthorized before commit. Actual verdicts have audit records. Downloads require CLEAN plus a matching persisted scanner receipt. Human evidence verification is a separate Bureau review and cannot override quarantine. Registration copies an existing Gmail scan receipt only for identical bytes; otherwise it keeps the case file pending.

Before declaring operational: verify authenticated health through the private ingress, scan an approved harmless test attachment and confirm its exact-byte hash/receipt/download, then use the official EICAR test file in a controlled development case to verify INFECTED and blocked download/review. Test timeout, incorrect credentials, unreachable backend, invalid result binding and cross-Bureau denial. Do not upload confidential production evidence during initial acceptance. Automated transport tests use explicitly mocked ClamAV replies and do not prove actual malware scanning. No real end-to-end scan has succeeded until this deployment is configured and tested.
