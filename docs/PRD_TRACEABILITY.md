# PRD → prototype → deployed schema

The schema names below were verified in `supabase-schema.snapshot.json`. The app's live adapter remains disabled; these are mappings for the integration work, not claims that the demo writes to these tables.

| PRD capability | Prototype implementation | Verified deployed schema / contract | Acceptance coverage |
|---|---|---|---|
| Identity and roles | Demo-only perspectives; assignment/Bureau scope; Admin has no case bypass | `users.external_subject`, `user_role_assignments`, `user_bureau_memberships`; trusted Auth mapping missing | Unit role/read/action denial tests; browser Auditor/Admin isolation |
| Draft intake | Original Marathi/Hindi/English; precomputed translations; corrected extraction verification; register/associate/reject; idempotent replay | `inbound_messages`, `case_submissions`, `submission_translations`, `submission_case_links`; atomic confirmation function still needed | Unit idempotency and unauthorized intake; browser verification → registration |
| Case registry and detail | Search, Bureau/priority/state filters, sort, pagination, metadata, comments, transitions | `cases`, `case_status_history`, `case_comments`, `transition_case_status`; lifecycle reconciliation needed | Unit legal/illegal/stale transitions; browser notes and refresh |
| Ownership | Scoped assignment, transfer request, Supervisor review, single lead update, deadline retention | `case_assignments`, `case_transfers`, `case_transfer_approvals`; `request_case_transfer`, `decide_case_transfer`, `complete_case_transfer` | Unit transfer/replay/stale scope tests |
| Investigation work | Four-column Kanban, adjacent-stage dragging and selector, task creation | `case_work_items`; dedicated authorized create/update contract needed | Unit stage/permission/closed-case rules; browser stage persistence |
| Evidence | Local .txt attachment, SHA-256, preserved same-name versions, provenance, preview/download, separate DOCUMENTS scope | `documents`, `document_versions`, `evidence_items`; private storage bucket/policies absent | Unit version retention and grant separation; browser evidence and access tests |
| Access requests | Discovery-only sanitized IDs, purpose/scope/duration, Supervisor approve/reject, independent details/document grants with expiry | `case_access_requests`, `case_access_grants`, `case_access_grant_approvals`; `request_case_access`, `approve_case_access_request` | Unit no forged claims, expiry and separate scope; browser details/document isolation |
| Related cases | Advisory evidence-backed fixture; explicit relationship confirmation, no merging | `match_runs`, `match_candidates`, `case_relationships` | Unit no auto merge; browser finding review |
| Conflict Sentinel | Synthetic action sequencing rule, exact fictional action/rule references, human review reason | `regulatory_actions`, `conflict_rules`, `conflict_findings`, `conflict_finding_actions`, `policy_versions` | Unit and browser review with unchanged cases |
| Contradiction detector | Side-by-side source references and explicit 24/16 faculty claims; uncertainty; document-scope filtering | `evidence_claims`, `claim_source_references`, `document_extractions`, `contradiction_findings` | Source fixtures, scoped finding reads, human review workflow |
| Dependency graph | React Flow, typed links, node detail/keyboard selection, filters, zoom/minimap, confirmed provenance; cycle rejection | `case_relationships`, `case_relationship_types`; `review_case_relationship`, `prevent_dependency_cycle` | Unit cycles/self-link/duplicate rejection; browser reverse-cycle rejection |
| Resolution Quality Gate | Dynamic checklist, current evaluation snapshot, atomic demo-command revalidation, explicit human disposition/reopen | `closure_checklists`, `closure_checklist_versions`, `closure_requirements`, `closure_evaluations`, `closure_evaluation_items`, `closure_approvals`, `closure_exceptions`; `dispose_case` needs freshness/current-state review | Unit forged/stale/missing/authority tests; browser blocked vs passing disposal |
| SLAs and calendar | Relative-date seed, example 14-day new-case deadline, retained hold/transfer dates, monthly calendar | `sla_policies`, `sla_policy_versions`, `sla_instances`, `sla_events`; official policies/calendar/jobs not configured | Unit retention; browser month navigation and breakpoints |
| Analytics and export | Authorized cohort metrics, 7/30/90 days, source-derived charts, CSV formula protection, scoped export audit | `export_case_metadata`, `audit_events`; production historical reporting contract needed | Unit KPI reconciliation/unauthorized export; browser route rendering |
| Audit | Retained actor/action/target/reason/timestamp in local command history; scoped search/export | `audit_events`, `reject_audit_mutation`; live append-only behavior not comprehensively tested | Unit actor/audit scope; browser timeline |
| Settings and Help | Validated local profile, save/discard, working notification/appearance preferences, reset; topic/search FAQ and keyboard guide | Not mapped to an invented deployed preferences table | Browser save/refresh/discard; demo reset UI |

## Honest boundaries

The prototype does not ingest live email, call a model, provision accounts, send messages, publish official policies, run SLA workers, store remote documents or perform government operations. Local persistence and local audit can be changed by the browser owner; they are demonstration features, not production authorization. Live database concurrency, performance, recovery, backup and restricted-user tests remain open.
