# Security review and release boundary

The actual hosted migration transaction and restricted-login negative checks passed; see MIGRATION_REVIEW.json and HOSTED_NEGATIVE_RESULTS.json. Existing rows, source function definitions, managed Auth schema, read lease and source exposure were preserved. Both new privileged roles are NOLOGIN, NOINHERIT, NOBYPASSRLS, own no tables and cannot self-activate their release control. The Gmail SECDEF function has an empty fixed search_path and row_security=on; browser anon/authenticated/service roles cannot execute it. Only the private gateway has execution permission. Tokens and PKCE verifiers are AES-256-GCM ciphertext, with separate state/connection/mailbox AAD bindings.

OAuth state is random, stored hashed with a short expiry, tied to the online-verified administrator and session UUID, and consumed atomically once. Completion is also one-use. Wrong mailbox identity prevents token storage. Provider refresh is server-only, persists a rotated credential, validates readonly scopes, and exposes only nonsecret status/error codes to the administrator UI. Cron requires its independent bearer secret. Neither consent nor an environment toggle enables complaint writes. Actual ingestion additionally checks the inactive-by-default database operations release, exclusive worker lease, current scoped review officer, active Bureau and prior real-message verification for scheduled runs.

Original email records, raw MIME, attachment bytes/hashes, human review defaults and service audit are committed together. Message IDs are unique per connection; normalized content only flags a duplicate candidate and never silently merges or discards a separate email. Supported original attachments are copied to protected canonical case evidence only on human registration. Registered-source access is rechecked against every linked case, including document scope for attachments; transfer removes the prior officer's source/byte access. The disposable test verifies the actual independent source/destination transfer workflow and denial afterward.

Post-migration Supabase security advisors report the same existing warnings: seven mutable-search_path legacy trigger/helper functions, the intentional authenticated self-session revocation RPC (advisor 0029), and disabled leaked-password protection. No new Gmail/helper function is flagged. Raw advisor metadata and remediation links are retained in SECURITY_ADVISORS_FINAL.json (with the earlier snapshot retained separately). The self-revocation function is deliberately authenticated-callable to revoke only the calling session; it does not reopen case RPCs. Legacy path warnings and provider password-security settings still need owner hardening review before a production release; they were not silently changed as part of Gmail setup.

Not established by these checks: current positive provider-issued-JWT operational acceptance, final browser/mailbox consent, a real email ingestion, production restricted-scope approval, production-volume scheduling, a hosted malware scanner, or production semantic/translation worker acceptance. The last three remain separate engineering/release work. No full-system Live Mode, protected case read activation or hosted complaint write activation has occurred. User manual acceptance remains required. This document is not independent activation approval.
